# Workspace Rules and Memory: Resume & Career Intelligence

## 1. Absolute Truth and Verification (Zero Fabrication, Zero Extrapolation)

**Core Mandate:** Under no circumstances should an agent ever invent, extrapolate, or assume a technology, framework, tool, library, or certification just because a Job Description (JD) requests it.

- **Exclusive Truth Sources:** Only technologies and accomplishments explicitly documented in `main.tex`, `achievements/ACHIEVEMENTS.md`, or verified in repository code may appear in tailored resumes, cover emails, interview answers, or ATS reports.
- **Unverified Terms Are Gaps:** If a JD asks for a skill not backed by verified evidence (e.g., Next.js, JWT, Express, Jest, Babel, Java, Go, Kafka, .NET, Terraform), it must be reported plainly as a **Real Gap** or excluded. Never add it to satisfy an ATS score.
- **Specific Verified Ground Truths:**
  - **Front-End:** React.js (React 19), Vite, Tailwind CSS, SCSS, Webpack (Full Cycle production), HTML5, CSS3, Responsive Design. *(NOT Next.js, NOT Babel).*
  - **Node.js / Back-End:** Node.js, NestJS (Fastify), Prisma, Python (Django, FastAPI), Symfony. *(NOT Express).*
  - **Testing:** pytest (Full Cycle production), Vitest, Playwright (DevATS). *(NOT Jest).*
  - **Build & Asset Tooling:** Webpack (Full Cycle production asset compilation), Vite (DevATS).
  - **Authentication & Security:** Session cookies, security headers, token management, Nginx transport hardening. *(Do not write JWT unless explicitly confirmed in code).*
  - **Commercial Production Experience:** 5+ years in tech, with 3+ years dedicated to software engineering (Full Cycle: Python/Django, PHP/Symfony, PostgreSQL, MySQL, Redis, Webpack/SCSS/SSR, Docker, CI/CD).
  - **Personal Deployed Projects:** React 19, NestJS, FastAPI, Model Context Protocol (MCP), multi-agent workflows.
  - **Never State or Imply 3+ Years of React or TypeScript:** The 3+ years of professional engineering was focused on backend (Python, PHP, RESTful APIs, PostgreSQL) and server-rendered interfaces. React and TypeScript are evidenced strictly across deployed personal applications. The summary must always preserve this explicit distinction.

## 2. Style and Output Guardrails
- **No Em Dashes or En Dashes:** Never use `—` or `–` in any user-facing text, reports, emails, connection notes, or tailored LaTeX documents. Gabriel considers them an AI tell. Use commas, colons, parentheses, or periods.

## 3. Base Source is Always `main.tex` (Zero Context Leakage, Zero Skill Bloat)
- **Always Anchor to `main.tex`:** When tailoring, ALWAYS copy directly from `main.tex` as the base template. Never reuse or carry over skills blocks from previously tailored files in the context window.
- **No Granular Skill Inflation:** Never artificially bloat or split the Skills block with generic sub-skills (e.g. `HTML5, CSS3, Tailwind CSS, SCSS, Webpack, Responsive Web Design`) unless the target JD literally and explicitly demands those exact tokens. Keep the Skills section clean, concise, and structured like `main.tex`.
